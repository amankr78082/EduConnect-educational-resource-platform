EduConnect

A University ERP + LMS platform for syllabus-based learning, teacher interaction, subscriptions, quizzes, live classes, notes, videos, and academic workflow management.

React + TypeScript Node.js API MySQL Role Based Access Control ERP + LMS

Prepared for interview explanation, project viva, and company discussion.

1. Project Overview

EduConnect is a centralized academic resource platform for university students. The main problem it solves is scattered learning material: students often search across WhatsApp groups, Telegram channels, random PDFs, and YouTube playlists. EduConnect organizes everything by university syllabus hierarchy.

University -> Course -> Branch/Program -> Scheme -> Semester -> Subject -> Unit -> Topic -> Notes / Videos / PYQs / Quizzes / Live Classes

The project also includes ERP-style control for admins: academic hierarchy management, teacher approval, subject-wise teacher assignment, content approval, subscription verification, audit logs, and maintenance request workflow.

2. Main Roles

Student

Accesses syllabus-based learning resources, notes, videos, PYQs, quizzes, live classes, progress, bookmarks, subscriptions, and teacher doubt chat.

Teacher

Uploads academic content only for assigned subjects, creates quizzes, uploads PYQs/solutions, schedules live classes, and tracks quiz performance.

Admin

Controls academic hierarchy, users, teacher approval, teacher assignment, content approvals, subscriptions, delete requests, and analytics.

Maintenance

Suggests academic hierarchy changes and sends requests to admin. Maintenance does not directly publish critical changes.

5. Role Based Access Control

RBAC is implemented using user_roles. Routes are protected using a React role guard. Admin has broad access. Teacher, student, and maintenance users are limited to their respective dashboards and actions.

  • Admin: Full control and approval authority.
  • Teacher: Can manage content/quizzes/live classes for assigned subjects.
  • Student: Can consume resources and request subscription access.
  • Maintenance: Can create hierarchy update requests for admin review.

6. Academic Hierarchy Workflow

  1. Admin creates university, course, branch/program, scheme, semester subjects, units, and topics.
  2. Admin approves teacher accounts.
  3. Admin assigns teachers to specific subjects.
  4. Teacher uploads notes, videos, PYQs, quizzes, and live class links for assigned subjects.
  5. Admin reviews/approves content where approval workflow is required.
  6. Student opens syllabus and consumes resources topic-wise.

7. Student Learning Workflow

Login -> Dashboard -> Syllabus -> Select University/Course/Semester -> Subject -> Unit -> Topic -> Notes / Video / PYQ / Quiz

Students can view free preview content. Premium semester subscription unlocks full subject resources, full quiz question bank, downloadable notes, videos, and PYQs.

8. Subscription Workflow

  1. Student selects semester premium plan.
  2. Student scans PhonePe/UPI QR and pays.
  3. Student uploads payment screenshot and transaction ID.
  4. System creates subscriptions and payments records with pending status.
  5. Admin reviews screenshot and activates/rejects subscription.
  6. After approval, student receives premium access for that semester.

9. Quiz Workflow

  • Teacher/admin creates quiz, questions, and options.
  • Student starts quiz from Quiz Arena.
  • Free students access up to 20 questions per subject quiz.
  • Premium students access the full quiz bank where available.
  • Timer is 20 seconds per question.
  • On submit/auto-submit, system stores one quiz_attempts row and multiple student_answers rows.
  • Leaderboard is generated from completed quiz attempts.

11. Important Relationships

  • app_users.id -> profiles.user_id and user_roles.user_id
  • universities.id -> courses.university_id
  • courses.id -> branches.course_id
  • branches.id -> schemes.branch_id
  • schemes.id -> subjects.scheme_id
  • subjects.id -> units.subject_id, content.subject_id, quizzes.subject_id, previous_papers.subject_id
  • units.id -> syllabus_topics.unit_id
  • teacher_assignments.teacher_id links teacher user to teacher_assignments.subject_id
  • quizzes.id -> questions.quiz_id -> options.question_id
  • quiz_attempts.id -> student_answers.attempt_id
  • subscriptions.id -> payments.subscription_id

12. API / Backend Summary

The backend is a Node.js MySQL API. The frontend uses a custom mysqlClient wrapper that provides Supabase-like calls such as from(table).select(), insert(), update(), delete(), and rpc().

  • npm run api starts the MySQL API server.
  • npm run dev starts the Vite frontend.
  • API base URL is configured by VITE_API_BASE_URL.
  • Authentication uses local session storage and DB tables.

13. Interview Explanation Script

Short version: EduConnect is a syllabus-based LMS for university students with ERP-style admin control. It organizes notes, videos, PYQs, quizzes, live classes, subscriptions, and teacher interaction according to the academic hierarchy.

Detailed version: I built EduConnect using React, TypeScript, Tailwind CSS, Node.js, and MySQL. The system uses role based access control. Students access structured learning resources. Teachers upload content only for subjects assigned by admin. Admin manages hierarchy, teacher assignments, content approvals, subscriptions, and analytics. Maintenance users can raise academic update requests that admin approves before publishing.

14. Strengths Of The Project

  • Solves a real student problem: scattered academic content.
  • Uses structured syllabus hierarchy instead of random resources.
  • Includes real RBAC and subject-wise teacher access.
  • Has subscription/payment verification workflow with screenshot proof.
  • Stores quiz attempts and student answers in normalized DB tables.
  • Includes admin/teacher/student/maintenance workflows, making it more than a simple LMS.

15. Possible Future Improvements
